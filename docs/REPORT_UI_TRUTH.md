# Report UI Truth

How report, dashboard, and PDF-adjacent UI must render truth. Every surface that presents report data must derive it from the same backend source.

---

## The Core Rule

> Report title, source count, platform labels, business/context labels, API response, dashboard, and PDF must all agree.

If the API says the report includes 2 sources (Patreon, Substack), then:
- The report detail page says 2 sources.
- The dashboard says 2 sources (from the last run).
- The PDF says 2 sources.
- The report list shows the same platform labels.

Any discrepancy between surfaces is a **trust failure**.

---

## Current Report Direction

Generated reports should remain:

- narrative-first, not dashboard-first
- creator-facing and strategic, not internal or robotic
- trust-preserving and honest about data limits
- less boxy/card-heavy than the earlier dashboard-style presentation
- close in spirit to `/sample-report` without cloning it
- precise enough to be useful, but not over-precise

The current direction is a report document: clearer business headline, scannable key findings, explanatory concentration framing, stronger opportunities/action plan, and methodology that improves trust without taking over the page.

---

## Titles From Canonical Report Truth

Report titles come from the backend report payload. The frontend does not construct or modify report titles.

- Do not generate a title from the current workspace state.
- Do not use a cached or stale title from a previous run.
- If the backend returns a different title format after a pipeline change, the frontend renders the new format.

---

## Source Count and Platform Labels From Snapped Run Sources

The source count and platform list shown in any UI surface must come from `ReportRunSource` records for that specific run — not from current workspace state.

| Surface | Source of Truth |
|---|---|
| Report detail header ("3 sources") | `ReportRunSource` count from backend API |
| Dashboard source summary | `ReportRunSource` data from latest completed run |
| PDF source attribution | `ReportRunSource` data baked into PDF at generation time |
| Report list entry | `ReportRunSource` summary returned by list endpoint |

The frontend must not recount sources by querying workspace data or making assumptions about what was included.

---

## Business-Driving vs Context-Only Labels

Some sources drive the financial narrative (Patreon, Substack, YouTube normalized CSV). Others are context-only (Instagram, TikTok).

**Labeling rules:**
- Show business/context distinction only where it adds meaningful clarity — not on every card.
- Do not label a context-only source as "earnings data."
- Do not show "0 revenue sources" as an error state when a context-only source is included with a business source.
- Use plain language: "earnings data" or "audience data," not "full_support" or "supported_as_context."

---

## Snapshot Basis / Coverage Notes

Reports are based on a data snapshot, not live data. When coverage is relevant:
- Show the coverage period (date range of data in the run).
- Show coverage gaps clearly if a platform has partial data.
- Do not imply the report reflects "current" data unless the snapshot is recent.
- Frame thin-data caveats around this upload, export, or data pull, not around internal artifacts or product failure.

Example: "Based on data through March 2025" or "Covers 12 months of Patreon data."

---

## Paid Subscribers vs Total Subscribers Labels

- The headline subscriber KPI must be **paid subscribers only**.
- If total subscribers (including free-tier) are shown, they must be labeled separately: "Total subscribers (incl. free)" or "Audience."
- Never use "subscribers" without qualification if the number includes free Substack subscribers or $0 Patreon patrons.

See `docs/FRONTEND_BACKEND_CONTRACTS.md` and `creator_optimizer/docs/METRICS_SEMANTICS.md` for full definitions.

---

## "What We See" / "Signals Worth Watching" / "Next Best Move"

These sections of the report render narrative content generated by the backend. Rules:

| Section | Rule |
|---|---|
| "What We See" | Render backend-generated summary. Do not rephrase or shorten. |
| "Signals Worth Watching" | Render backend-generated signals. Do not filter based on frontend tier logic. |
| "Next Best Move" | Render backend-generated recommendations. |
| Teaser content | Free/Report-tier users see teaser. Gating is backend-driven via entitlement check. |

Do not generate narrative content on the frontend. Do not mix backend-generated content with frontend-constructed copy in the same section without clear visual distinction.

---

## Presentation Guardrails

- Money in prose should generally be whole-dollar formatted unless cents are truly necessary.
- Percentages in prose should generally be humanized to 0 or 1 decimal place unless finer precision materially helps interpretation.
- Do not invent unavailable data, imply false certainty, or add fake precision to make copy sound smarter.
- Audience/content/discovery signals must not imply revenue unless revenue evidence actually exists.
- Thin-data caveats should stay honest, but they should read like creator-facing guidance rather than internal diagnostics.
- Do not reintroduce customer-facing `Artifact JSON` or `JSON artifact` fallback wording in normal report UI.
- Do not drift the generated report back toward a box stack of widgets, cards, and repeated KPI chrome when the content is better served as a narrative section.

---

## Avoid Stale or Misleading Report Summaries

- The dashboard reflects the **last completed report run**, not the current workspace state.
- If no report has been run, show an empty/onboarding state, not a stale or fabricated summary.
- If a report is in progress, show a loading/generating state, not the previous run's data labeled as current.
- After a new report completes, refresh dashboard data — do not serve stale cached results.

---

## Do / Don't Summary

| Do | Don't |
|---|---|
| Show source count from `ReportRunSource` records | Recount sources from current workspace |
| Show platform labels from API payload | Construct platform lists locally |
| Show paid subscriber count labeled as "paid" | Use "subscribers" when the number includes free tiers |
| Show coverage period from the run snapshot | Imply the report reflects live or current data |
| Show report title from backend payload | Construct or modify report titles locally |
| Show teaser for gated content when backend says not entitled | Hide sections based on frontend plan logic |
| Refresh dashboard after new report completes | Serve stale dashboard data after a new run |
